# OrbitParts audit (2026-11-14)

A read-only deep dive into the whole app: seven parallel code reviews (BOM and parts; inventory, COTS,
scan and map; To Fab, drawings and assembly; CAD, 3D and versions; Onshape, MCP, API and security;
app shell and design system; data, ops and tests), plus a walk through the live site at phone width.
Nothing was changed, run against the database or deployed.

Every finding cites file:line. ✔ marks the ones I re-read in the code myself after the reviewers
reported them; the rest come from the reviewers, who were told to cite only code they had read.
Severity: **H** high, **M** medium, **L** low. Effort: S (hours), M (a day or two), L (more).
Line numbers are as of commit 302943b; the fixes below moved many of them.

## 2. Bugs and logic, by area

### BOM, parts and Recent actions
- **M** Undo writes around `applyPartChanges`: no `lockRelease` when going back into Released, no `fabFinishedAt` / `cotsInStockAt` / `stageAt` upkeep, no `pushCardToItem` (`parts/undo.ts:84-88`). Fix: run undo through `applyEachPartChanges` with "only if unchanged". M.
- **M** `AutoRefresh` runs an Onshape check (up to 45 s) as a server action on mount and every 5 min, so a tap right after opening a system page queues behind it (`bom/AutoRefresh.tsx:17-27`). Move it to a route handler. S.
- **M** Recent actions declares `Box` inside render and re-renders every second, which remounts every link and image each second, and its "12s ago" text breaks hydration (`actions/RecentActions.tsx:203,411-417`). S.
- **M** Thrown permission errors crash the page instead of showing a message: BomView save inside `startTransition` (`BomView.tsx:143-150`); Unmerge shown to everyone but needs `shape` (`PartCard.tsx:436-471`). Have actions return `{ error }`. S.
- **M** The visit cookie is shared by all tabs, so edits get the wrong page and Revert scope (`shell/VisitTracker.tsx:30`). Revert of a visit can undo another tab's edits. S.
- **M** CAD Team Bulk edit and Kanban skip the mandatory Release checklist (`BulkEditBar.tsx:37`, `KanbanView.tsx:33-38`). S.
- **M** Bulk edit applies to selected parts the current filter hides (`BomView.tsx:381`). S.
- **M** A note typed in the part window is lost when closed with Esc or back (save on blur only, `PartDetails.tsx:329-332`). S.
- **L** `redoAction` doesn't check that the batch is the member's (`undo-actions.ts:49-55`).
- **L** COTS statuses missing from the status filter and painted grey in 3D (`BomView.tsx:301-306`).
- **L** A Kanban drop of a made part on a COTS-only column silently resets it to Not Started (`KanbanView.tsx:28-38`).
- **L** `addManualPart` writes no `part_history` (no undo, not in Recent actions) (`parts-actions.ts:88-101`).
- **L** Delete dialogs say "can't be undone" although deletes go to Recently deleted for 30 days (`RobotSettings.tsx:66`, `SystemSettings.tsx:60`).
- **L** Robot/system actions skip UUID checks (500s), and deletes use `requireAdmin` instead of the mode check (`robots/actions.ts:58-153`).

### Onshape, MCP, API, security
- **M** The panel sign-in code can be phished: anyone can request a code and send a member the connect link; one click gives a 60-day cookie that works on the whole site, not just the panel, and can't be revoked (`api/panel/login/route.ts:11-31`, `onshape/connect/page.tsx:17-45`, `lib/auth.ts:33`). Confirm a short code; add a revocable epoch; limit the cookie to panel routes. M.
- **M** No timeouts on Onshape calls, and the token refresh runs while holding a `FOR UPDATE` row lock and a pool connection (`onshape/client.ts:78,132,263`; pool size 12). One hung refresh can stall every page. S–M.
- **M** Onshape network failures aren't turned into `OnshapeError`, so an outage crashes the panel tiles to the error page (`client.ts:263`, `UpdateTile.tsx:48,62`). S.
- **L** Upload size and type aren't enforced: the presigned PUT signs neither, and the server trusts the client's size (`storage/r2.ts:59`, `files-actions.ts:38,64`).
- **L** `frame-ancestors` allows framing on every path, and SameSite=None panel cookies work site-wide; POST routes have no Origin check (`next.config.ts:28`).
- **L** `part-data` POST and the STEP-export GET spend Onshape calls with no capability check (`api/systems/[systemId]/part-data/route.ts:11-20`).
- **L** Header injection through the part number in `content-disposition` (`onshape/partFile.ts:39`).
- **L** Possible open redirect: `safeNext` accepts `/\t/evil.com` (`lib/safeNext.ts:3`). Low confidence.
- **L** Database TLS uses `rejectUnauthorized: false` (`db/index.ts:16`); pass Supabase's CA.
- **L** Secrets reused across purposes: the panel HMAC uses `ONSHAPE_TOKEN_KEY`, and MCP confirm tokens fall back to `CRON_SECRET`.
- **L** MCP: JSON-RPC batches are unbounded and parallel; `search_inventory` has no limit; every write says `destructiveHint: false`, including `undo_batch` (`api/mcp/.../route.ts:80`, `registry.ts:154`).
- **L** `POST /api/panel/login` needs no sign-in and has no rate limit.
- **L** The dormant pool-account fallback borrows another member's Onshape account on a 403 (`sync/refresh.ts:17-37,87`): a confused deputy. Delete it.

Coverage: all 49 route handlers and all 175 exported server actions were checked for an auth call (all have one); every MCP write tool was checked for capability checks.

- **H** ✔ Migrations and deploys aren't ordered: `migrate.yml` and `deploy.yml` start on the same push, so column drops like 0092 break the live code until the switch, and a rollback leaves old code on the new schema. One workflow: test → migrate → deploy; drop columns a push later. S.
- **M** Every deploy restarts the server in place: ~27 short outages a day, and in-flight model builds and commits get killed. A broken release stays live up to 90 s, and the health check only fetches `/login` (`deploy/release.sh:21-44`). Blue/green on two ports with a `/api/ready` check. M.
- **M** Redeploying the live commit deletes the running release, leaving nothing to roll back to (`deploy/release.sh:12-16`). S.
- **M** The old Vercel project can wake on 6 Dec with production secrets and run keep-alive (backup and purge) twice (`vercel.json`). Disconnect it and rotate what it holds. S.
- **M** Restore leaves stock out of step with its moves, and part_history rows newer than the backup undo to stale values (`storage/restore.ts:87-101`). Backups aren't one snapshot either (20 parallel selects, `backup.ts:58-60`). S–M.
- **M** Nothing reports server errors: no `instrumentation.ts`/`onRequestError`, no `global-error.tsx`; `afterResponse` failures only reach journald. S–M.
- **M** No test checks that server actions call a permission guard, and `statusChangeDenied` reads outside the write transaction (`lib/mode.ts:51-90`). S.
- **M** The 4 known-failing DB tests come from test setup, not app logic: migrations seed a few categories (one of them a sheet), so `DEFAULT_CATEGORIES` never load and uncategorised test items fall back to the sheet category with need 0. Give the test items a category. S (traced, not run).
- **L** Missing indexes: `parts.stage_at` (read on every navigation), `inventory_moves.part_id`, `parts.released_version_id`, `review_comments.done_version_id`, `part_releases.version_id`, `cad_updates.robot_id`.

## 3. Free-tier and performance

Egress (the 11 Nov outage):
- ✔ Global search reads everything uncached (see #6).
- Layout reads recent arrivals per member, uncached, on every navigation and save (`data/seen.ts:32-62`, no index on `stage_at`). Cache the team-wide rows and filter in memory. S.
- Every 3D view selects the whole `onshape_cache.payload` (built, draft and plans), sometimes twice, but uses only `built` (`model/build.ts:59-62,106-161`). Select `payload->'built'`. S.
- CAD pages re-read every comment and every version's `changes` JSON on each comment action (`data/cadReview.ts:170-177,245`). The Onshape panel's comments page loads the whole review. S–M.
- Inventory: groups, conditions, open orders and thumbnails are read uncached on every load (`data/inventory.ts:111-197`). Every stock tap re-reads the 3 settings tables inside the transaction (`inventory/moves.ts:42`) and re-sends the whole shelf (`revalidatePath`). S–M.
- Every batch list downloads full `layoutData` (up to 5,000 placements) just to read the Onshape URL (`data/groups.ts:85-101`). S.
- Zivudim page visits open a write transaction and read full parts rows twice (`factory/autoPack.ts:18-23`). S.
- The nightly backup reads the biggest tables in full every day and gzips them synchronously on the single Node thread (`backup.ts:58-63`). Skip when nothing changed; stream it. M.
- The parts cache counter is global, so one tap on any robot drops every parts cache entry (`cache.ts`). Per-robot counters later. M.
- Nothing prunes `onshape_cache` (immutable per-revision keys), `part_history`, `inventory_moves`, `ai_logs`, `part_versions` or `deleted_records`. The database cap is 500 MB, and the StorageBox only warns about R2. S–M.

Server CPU (1 OCPU):
- Part shape measuring runs `gunzipSync` and brute-force wall thickness on the server (`review/review.ts:46-91`, `rules.ts:550-580`). Move it to the CAD member's browser. M.
- Auto Layout nests on the server and again in the browser on every input change, on the main thread (`BatchLayoutDialog.tsx:109-125`); `flatCache` never empties (`batchLayout.ts:37`). M.
- The spreadsheet import makes ~9 round trips per row inside one long transaction (`inventory/actions.ts:592-692`). M.
- The in-memory cache is capped by count (300 entries), not by size, and `structuredClone`s every hit (`cache.ts:43-76`). S.

Browser:
- 3D: no `forceContextLoss()`, so remounts leak WebGL contexts until the main view goes blank (`viewer/stage.ts:580-585`); every arriving file repaints the whole robot (`paint.ts:267-286`); measuring starts before topology arrives (main-thread fallback); mesh files could be about half the size (Uint16 indices, quantised positions, `mesh.ts:127-155`); the CAD page downloads the whole robot even when one system is isolated (`CadReview.tsx:149`).
- Shell: PartDetails (763 lines) and InventoryPopup (910 lines, which pulls in ShopMap) ship on every page. Load them with `next/dynamic` on first open. M.
- `Appearance.tsx:165,195` registers non-passive `wheel`/`touchmove` on `window`, so every scroll on every page waits for the main thread. S.
- `FastLink` fully prefetches on `touchstart`, so scrolling the phone drawer renders pages on the VM (`FastLink.tsx:22-25`). S.
- Live: the Shop Fab page HTML was 1.3 MB on a phone.

## 4. UX, UI and design

### What I saw on the live site (phone, 375 px)
- ✔ **No search on phones outside robot pages.** The top-bar search is `max-md:hidden` unless on a part page (`TopBar.tsx:59`), and it isn't in the drawer either. On Home, Inventory and Orders a student can't search.
- **Home is four big pictures and nothing else.** On a phone that's three screens of scrolling with one fact ("Blitzer · 0% complete"). Shop Fab (the Build Team's main page) isn't on it.
- **Shop Fab cards don't show the part's name.** The Released cards show a picture, status, material and machine; for a pale plate on a pale background the picture is nearly blank, so you can't tell what to make. The name and number should always show.
- **Inventory on a phone opens with admin tools:** Import / Export spreadsheet, Move and Delete sit above the add box, with nothing selected. The heading is doubled ("INVENTORY / Inventory").
- **The robot dashboard truncates** ("Factor…", "1 releas…") in the 3D Printing / Factory row.
- ✔ Nav links are 32 px tall and the chevrons 32 px or less on a coarse pointer, under the 36 px rule: 62 of 120 visible controls on Shop Fab were under 36 px.

### Touch targets (the shop's biggest UX tax)
The primitives don't carry the rule: `.btn`/`.input` are about 32 px (`globals.css:601-612`), so 80 call sites add `pointer-coarse:min-h-*` by hand and many don't. Worst offenders:
- the BOM card's done-counter − / + (~20×16 px), the most-tapped control in the shop (`PartCard.tsx:422-430`);
- the inventory Spread − / + / ✕ (`InventoryPopup.tsx:368,390,396`), list and table steppers, and tags (`ItemCard.tsx:164-180`);
- the batch strip: maker, priority, Auto Layout, Remove, Delete fab and G-code buttons (`BatchCard.tsx:263-750`);
- the left nav (`LeftNav.tsx:302,83,209,222`) and Undo/Redo (`UndoRedo.tsx:95`);
- Recent actions' Revert and ✕ (24 px, side by side).

Fix: build `pointer-coarse:min-h-10` into `.btn*`/`.input`, and add `Chip`, `IconButton` and `Stepper` primitives (five copies of the stepper exist today in different sizes).

### Flows
- Counting a part with a big quantity is one tap per piece, and List view can't count at all (`PartCard.tsx:415-433`, `PartListRow.tsx`). Long-press "+" or tap "3/24" to type a number or mark "All done". Uses `add`, so it's safe for concurrent taps.
- To Fab: moving parts between sections relies on HTML5 drag-and-drop, which phones don't run reliably (`FabView.tsx:291-296`). Add a "Move to… / Add to batch…" menu. "What to make next" ignores priority and deadline: batches sort by name, so "Laser 3/11" comes after "Laser 21/10" (`data/groups.ts:88`). Deleting a batch is instant and permanent, G-code included (`BatchCard.tsx:432`).
- Inventory: every place reads the same "map icon · dot · Drawer". Names are hidden on purpose and all zones are now one colour, so "where is it?" always means opening the map (`inventory/places.ts:38,64-67`). See Decisions. No filter for items with no place. Opening an item still runs as a server action, so it queues behind saves (`InventoryPopup.tsx:96`); move it to `/api/reads`. Scan only fills the search box, and a UPC never matches: offer "remember this code on item…" using `aliases`.
- CAD on phones: the comments column covers about half the view at load (`ReviewScreen.tsx:117-119`); touch gestures aren't documented anywhere; "☰ Versions" hides the Design check; a failed load gives no Retry.
- New members: a teamless member gets a read-only app with no explanation. ✔ The denied message says "Pick a team on your profile", but Profile tells non-admins that an admin sets it (`shell/mode.ts:137,160` vs `profile/page.tsx:63-67`). /pending has no refresh.
- Overridden fields are invisible (see #5). Show an "edited here" dot with "Use Onshape value".
- AI logs show "Revert change" to everyone, but only admins can use it, and the failure reads like a network error (`ai-logs/page.tsx:115`).
- Settings edits can be lost: one shared debounce timer for all categories, and colour changes are dropped on tab switch (`CategorySettings.tsx:43-59`, `SettingsView.tsx:258-273`).
- An Esc that nothing else handles collapses the side columns and remembers it for future sessions (`Shell.tsx:246-261`). Global Shift+letter shortcuts fire with a window open (`Shortcuts.tsx:213-221`).
- The service worker shows a saved copy when the server takes more than 8 s, while online, possibly from an old build with stale server-action IDs, and the bar says "Back online…" to someone who was never offline (`public/sw.js:28,109-115`).
- A layout error shows Next's raw page with no menus: there's no `global-error.tsx` or branded `not-found.tsx` (`(app)/layout.tsx:71-81`).

### Visual consistency
- 35 native `confirm()`/`alert()` calls instead of `Dialog` and toasts. Add a `useConfirm()` and undo toasts for reversible deletes.
- Light-only notice boxes: 17× `bg-rose-50`, plus emerald and amber boxes and `.btn-danger`, all unreadable in dark mode (e.g. `McpTokens.tsx:18-34`, `BomView.tsx:348`). Add one `<Notice tone>` primitive.
- Hard-coded colours: `sky-*` ×131 (ignores the hue slider), `#111318` ×23, a fixed yellow glow at ~1.4:1 on white, and a white badge on amber at ~2.1:1 on Home.
- Tiny text: 10–11 px classes (×206), and the UI-scale script shrinks them to ~7.5 px on a 1280 px laptop (`boot-scripts.ts:140`).
- Skeletons are invisible on dark (`.skeleton` at 6% black) and their outlines invisible on light.
- Two press-scale rules stack (0.96 × 0.98); text glyphs "✕"/"☰" are mixed with `<Icon>`.
- Members, Profile and New robot use a different heading style from every other page; "Orders" vs "COTS page"; "In-House" vs "In-house". Add a `PageHeader` primitive.
- The un-layered global `:focus-visible` rule beats every `outline-none` utility in Tailwind v4 (`globals.css:181-184`).
- Accessibility: part cards and the 3D canvas can't be reached by keyboard; inventory cards are `role="button"` wrapping links; the search dropdown has no combobox semantics; Dialog has no `aria-labelledby`, and no scroll lock on iOS.

## 7. Needs your decision

These touch an FRCBOM rule or an earlier decision of yours, so they weren't treated as plain bugs:

1. **Place names hidden + one zone colour.** Together they make every place look the same in lists. Bring back per-zone colours, or show a short zone letter or number?
2. **Configured variants share a part key** (`did:eid:partId`). The weight check can be fixed locally; keying BOM parts by configuration changes FRCBOM's identity.
3. **Arriving orders add "what was missing", not what arrived.** Keep it (FRCBOM), or add the real amount?
4. **Build Team can release a never-reviewed Not Started part with one tap** (`BUILD_STATUSES` includes Released). Intended?
5. **Oracle idle-reclaim**: upgrading the account to Pay-As-You-Go keeps Always Free resources free and stops idle reclaim, and the quota policy already caps compute. It's a billing-account change, so only with your OK and a $1 budget alert.
6. **GitHub plan**: check Settings → Billing for the Actions quota before the minutes run out; cut CI cost either way (build once, `paths-ignore` for `plan/`/`docs/`, cancel superseded runs).
